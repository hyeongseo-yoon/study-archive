# pwnable 기초: 워크플로우와 보호기법

## pwnable이 뭔지

**pwnable**: 컴파일된 실행파일(또는 그게 돌아가는 서버)을 대상으로, 메모리 버그(오버플로우, UAF, type confusion 등)를 악용해서 프로그램의 원래 의도를 벗어난 동작(셸 획득, 플래그 읽기 등)을 시키는 분야. "바이너리 익스플로잇"으로도 부름.


문제에서 주어지는 것과 직접 만드는 것:

| 구분 | 내용 |
| --- | --- |
| 문제가 주는 것 | 실행파일(바이너리), 가끔 소스코드, 가끔 libc |
| 직접 만드는 것 | 익스플로잇 스크립트 (관례상 `ex.py`) |

- `ex.py`는 바이너리를 조작하는 핵심 파이썬 스크립트**임
- pwntools로 대상 프로세스를 조종하는 **클라이언트** 역할 — 자신이 직접 공격하는 게 아니라, 공격 대상(취약한 바이너리)에 입력을 보내고 출력을 받는 쪽임
  - 로컬: pwntools가 바이너리를 자식 프로세스로 실행해서 stdin/stdout에 붙음
  - 원격: 서버 IP:포트에 소켓으로 연결함
  - 둘 다 pwntools 입장에서는 동일한 인터페이스로 처리됨(`process()` vs `remote()`)
- 보통 한 번 입력 넣고 끝나는 게 아니라, **leak → 오프셋 계산 → 페이로드 재조립 → 재전송**을 여러 번 반복하는 대화형 흐름임

## 전체 풀이 흐름

1. `checksec 파일명`으로 보호기법 확인
2. 소스코드 읽기 또는 디컴파일로 취약점 위치 찾기
3. pwntools로 `ex.py` 작성, 로컬에서 성공 확인

## 보호기법 확인

- **NX**: 켜져 있으면 스택에 쉘코드를 직접 올려 실행 못 함 → ROP 같은 기법 필요
- **PIE**: 켜져 있으면 바이너리 자체 주소도 매번 랜덤 → 주소 하드코딩 불가, leak부터 필요
- **Canary**: 켜져 있으면 단순 오버플로우로 return address 덮으면 바로 죽음 → canary 우회/leak 필요
- **RELRO**: Full이면 GOT overwrite 공격이 막힘


## 가장 기초적인 형태: 인접 변수 덮기

스택 버퍼오버플로우의 가장 단순한 형태는 return address나 포인터가 아니라, **바로 옆에 있는 로컬 변수를 덮어서 분기(조건문) 결과를 바꾸는 것**임.

예시:

- 배열 크기(`char buf[N]`)와 실제로 읽어들이는 바이트 수(`read(fd, buf, M)`)가 다를 수 있음
- `M > N`이면 `buf` 경계를 넘어 스택에 있는 다른 변수까지 덮어쓸 수 있음
- 로컬 변수들은 스택에 쌓이는 순서가 있고(컴파일러/아키텍처 의존), 오버플로우로 옆 변수를 건드릴 수 있음

이보다 한 단계 더 나가면, 덮는 대상이 정수가 아니라 **포인터 변수**인 경우도 있음 — 포인터 값을 덮으면 이후 그 포인터를 사용하는 코드(출력 함수 등)가 공격자가 원하는 주소를 가리키게 만들 수 있음.

## pwntools 핵심 API

### 연결

```python
p = process("./chall")         # 로컬에서 자식 프로세스로 실행
p = remote("127.0.0.1", 31337) # 소켓으로 연결 (로컬 docker든 원격 서버든 동일 인터페이스)
```

### 입출력

| 함수 | 역할 |
| --- | --- |
| `p.send(b"data")` | 그냥 바이트 전송 |
| `p.sendline(b"data")` | 끝에 `\n` 붙여서 전송 (가장 많이 씀) |
| `p.recv(n)` | 최대 n바이트 수신 |
| `p.recvline()` | 줄바꿈까지 한 줄 수신 |
| `p.recvuntil(b"...")` | 특정 문자열 나올 때까지 수신 후 버림 — 프롬프트 스킵용 |
| `p.recvall()` | 프로세스 종료까지 전부 수신 (디버깅/확인용) |
| `p.interactive()` | 셸이 떴을 때 터미널처럼 직접 입력하는 모드로 전환 |

### 오프셋 찾기

```python
payload = cyclic(50)        # 패턴이 겹치지 않는 문자열 생성
offset = cyclic_find(b"aaab")  # 그 패턴이 몇 번째 바이트였는지 역산
```

브루트포스로 패딩 길이를 하나씩 늘려가며 찾는 것도 가능하지만, `cyclic`/`cyclic_find`가 전용 도구임.

### 숫자 ↔ 바이트 변환

```python
p32(0x08048000)   # 4바이트 little-endian 패킹
p64(0x401234)     # 8바이트 패킹
u32(b"...")        # 바이트 → 숫자 (반대 방향)
u64(b"...")
```
주소/정수를 페이로드에 끼워 넣을 때 사용.

### ELF 정보 읽기

```python
elf = ELF("./chall")
elf.symbols['auth']    # 심볼 주소
elf.got['printf']      # GOT 엔트리 주소
```

### 디버깅

```python
context.log_level = "debug"  # 주고받는 바이트를 hex dump로 표시
```

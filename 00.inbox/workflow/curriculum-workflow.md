# 커리큘럼 워크플로우

새 커리큘럼을 짤 때는 아래 단계를 따른다.

**0단계 — 소스 등급 판단**
주제에 이미 검증된 권위 있는 코스/교재가 있는지 먼저 확인한다.
- **Tier 1** (있음: CS:APP, xv6, OSTEP, CLRS 등) — 그 커리큘럼을 그대로 따라간다. 새로 합성하지 않고, 로컬 환경(핸드아웃 위치, 실습 경로)에 맞춰 개인화하고 검증 방법만 명시한다.
- **Tier 2** (부분적으로 있음) — 여러 소스를 비교해서 직접 짜되, 레벨 순서마다 근거를 한 줄씩 남긴다.
- **Tier 3** (거의 없음: 니치하거나 최신이라 참고 자료 부족) — AI 리서치로 초안만 뽑고, 반드시 사람이 검증한 후 확정한다.

**1단계 — 진단**
완전 처음 배우는 주제가 아니면, 5문항짜리 체크리스트나 문제로 현재 지식 수준을 진단한다. 추가로 설명이 필요한 선수 개념이 있으면 그 개념들만 모아서 **Level 0**을 만들고 먼저 학습한다. 없으면 Level 0은 생략하고 Level 1부터 시작한다.

**2단계 — 레벨 구조화**
- 난이도/의존성 순서로 배열한다 — 앞 레벨이 뒷 레벨의 전제조건이 되도록.
- Level 하나는 한 학습 세션 안에 끝낼 수 있는 크기로 쪼갠다.
- Level마다 검증 방법을 명시한다 (자동 채점 스크립트, 실습 결과물, 또는 설명 가능 여부 등).
- Level마다 핵심 개념을 최소 1~2개 명시한다 — 이후 노트로 정리될 때 `#review` 태그 대상과 그대로 연결되도록.

**3단계 — 크로스 레퍼런스**
관련된 다른 커리큘럼과 개념 단위로 연결점을 명시한다 (예: "Level 3은 [[xv6-lab-curriculum]] Level 2와 개념 직결").

**4단계 — 진행현황 표기**
문서 앞쪽에 레벨별 진행상황 체크리스트 섹션을 둔다:
```
## 진행상황
- [x] Level 0: (해당 시) ...
- [x] Level 1: 핵심개념 요약 (노트: [[관련노트]])
- [ ] Level 2: ...
```

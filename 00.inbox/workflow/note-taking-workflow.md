# 노트정리 워크플로우

사용자가 "이제 공부한 내용 아카이브에 정리하자" 같은 말을 하면, 다음과 같은 과정을 거친다.


1. 사용자한테 설명한 내용을  소스로 삼아, 오늘 공부한 내용을 정리 및 구조화 해서 초안을 작성한다. 초안을 작성할 때는 배운 내용의 핵심 내용들을 적고, 글을 많이 적기보다는 줄바꿈, 단락 나누기 등을 적극 활용해서 내용을 구조화한다. 명령어나 코드의 경우에는 예시 코드블럭을 적극 활용하서 쉽게 이해할 수 있게 한다. 함수나 구조체 등 인터페이스가 있는 개념을 배울 때는 인터페이스 원형과 예시코드를 사용해서 정리한다.
   - **개념형 내용** (왜/어떻게 동작하는지가 핵심인 단일 개념 : OS 개념, 파일 시스템, 피터슨 알고리즘, 가상 메모리 등)은 정의 / 원리 / 이유 / 핵심 차이·포인트를 참고 틀로 삼되, 매 섹션에 기계적으로 강제하지 않는다. 내용 흐름에 안 맞으면 자연스러운 소제목으로 논리적으로 그룹핑한다.
   - **절차/레퍼런스형 내용** (무엇을 어떻게 쓰는지가 핵심인 내용: 함수 형식, 명령어, 툴 사용법, 옵션 정리 등)은 위 4항목 틀을 억지로 채우지 말고, 표나 예시 중심으로 정리한다.
   - 문장은 **음슴체**(~함, ~됨, ~있음)로 간결하고 짧은 호흡으로 작성한다.
   - 불릿·번호뿐 아니라 표, 코드블록, 소제목 등 마크다운 구조화 요소를 적극 활용해서 내용을 채운다. 
   - 목록 계층 구조를 활용한다 :  `-` 또는 `*` 뒤에 한 칸 띄우고 작성. 하위 항목은 한 번 들여쓰기 후 작성한다.
   - 새 **개념 노트**는 `00.inbox/templates/study-note.md` 템플릿으로 만든다 (`created` 작성일 자동 기입 + `#review` 태그). `tools/`·`reference/` 같은 레퍼런스형 문서는 복습 대상이 아니므로 상태 태그를 붙이지 않는다. 기존 노트에 상태 태그가 없어도 임의로 추가하지 않는다. (복습 시스템 상세는 CLAUDE.md Part 3 참고)
   - 다루지 않은  내용을 임의로 추가하지 않는다.

   - 기존 폴더 구조에 맞는 위치에 파일을 배치한다. (예시 : OS의 특정 개념과 관련된 내용을 공부하면 OS 폴더에 있는 해당 개념의 파일에서 배운 내용을 추가한다. 기존의 파일에 없는 새로운 개념을 공부했다면 새로 파일을 만든다.)

1.  사용자가 초안을 검토·수정한다. + 완료 후 커리큘럼 문서에 학습 현황을 업데이트한다.
2.  커밋을 요청 받았을 때 tools/github.md에 정리된 Conventional Commits 규칙을 사용한다.

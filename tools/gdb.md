# gdb — GNU Debugger

실행 중인 프로그램을 멈춰서 레지스터/메모리/변수 값을 들여다보고, 한 줄 또는 한 명령어씩 실행시켜볼 수 있는 디버거. Bomb Lab처럼 소스 없이 바이너리만 갖고 리버싱할 때 핵심 도구.

## 기본 흐름 제어

| 명령어 | 줄임말 | 기능 | 예시 |
|---|---|---|---|
| `break 함수이름` | `b` | 그 지점에 브레이크포인트(정지 표시) 걸기 | `break mystery` |
| `run` | `r` | 프로그램 처음부터 실행, 브레이크포인트에서 정지 | `run` |
| `continue` | `c` | 정지 지점에서 다음 브레이크포인트까지 계속 실행 | `continue` |
| `next` | `n` | 현재 소스 줄 실행 후 다음 줄로 (함수 호출은 통째로 건너뜀) | `next` |
| `step` | `s` | `next`와 같지만 함수 호출을 만나면 그 안으로 들어감 | `step` |
| `nexti` | `ni` | `next`의 기계어 명령어 단위 버전 (소스 줄이 아니라 명령어 하나씩) | `nexti` |
| `stepi` | `si` | `step`의 기계어 명령어 단위 버전 | `stepi` |

- `next`/`step`은 소스 줄 단위, `nexti`/`stepi`는 명령어 단위. 소스 없이 어셈블리만 볼 땐 `ni`/`si` 위주로 쓰게 됨.
- `next` vs `step`, `nexti` vs `stepi`의 차이는 동일하게 "함수 호출을 건너뛰냐(over) 들어가냐(into)"임.

## 값 확인

| 명령어 | 기능 | 예시 |
|---|---|---|
| `print 값` (`p`) | 변수/레지스터 값 출력 | `print $rax`, `print x` |
| `info registers 레지스터명` | 특정 레지스터 값 확인 | `info registers rdi` |
| `disas` | 현재 함수 전체를 역어셈블해서 보여줌 | `disas`, `disas mystery` |
| `x/NFU 주소` | 메모리 지정 위치를 포맷대로 덤프 | `x/s $rdi`, `x/4xb $rsp` |

### `x/` 포맷 문법
```
x/NFU 주소
```
- `N`: 개수
- `F`: 포맷 — `x`(16진수) `d`(10진수) `s`(문자열) `c`(문자) `i`(명령어)
- `U`: 단위 크기 — `b`(1B) `h`(2B) `w`(4B) `g`(8B)

예: `x/s $rdi` (rdi가 가리키는 문자열 보기) / `x/4xb $rsp` (rsp부터 1바이트씩 4개 16진수로) / `x/8xg $rsp` (8바이트씩 8개)

## 감시 (watchpoint)

| 명령어 | 기능 | 예시 |
|---|---|---|
| `watch 변수/메모리` | 그 값이 바뀌는 순간 자동으로 정지 | `watch buf[0]` |

"이 값이 어디서 바뀌는지 모르겠다" 싶을 때 사용. 한 줄씩 `next`로 추적할 필요 없이, `watch` 걸어두고 `continue`하면 값이 바뀌는 그 순간에 gdb가 알아서 멈춤 (라이브러리 내부 코드에서 바뀌어도 잡아냄).

## TUI 모드 (화면 분할)

| 명령어 | 기능 |
|---|---|
| `layout asm` | 현재 명령어를 자동으로 하이라이트하며 어셈블리 표시 |
| `layout regs` | 레지스터 값을 실시간으로 같이 표시 |
| `Ctrl-x a` / `tui disable` | TUI 모드 종료 |

`display/i $pc`로도 매번 정지할 때마다 현재 명령어를 자동 출력 가능 (TUI 없이 가벼운 대안).

## 0. 선수 개념 복습

**컴파일러 큰 흐름**
```
소스코드 → [Front end: Lexical → Syntax → Semantic]
         → 코드 생성 → [Back end: 분석/최적화 → 코드 생성] → 어셈블리
```
- Front end: 소스코드를 이해하는 쪽. 언어에 의존적. 오늘 배우는 Lexical Analysis(Scanner)가 첫 단계.
- Back end: 이해한 결과로 좋은 기계어를 만드는 쪽. 타깃 머신에 의존적.

**언어(Language)와 무한집합의 유한한 표현**
- 컴파일러 이론에서 언어는 문자열의 집합. 알파벳은 쓸 수 있는 문자의 집합(예: `{a, b}`).
- `{a, ab, abb, abbb, ...}` 같은 무한집합은 나열할 수 없으니 `ab*`처럼 유한한 기호로 규칙을 적어서 표현한다. 이게 정규표현식(RE)의 핵심 아이디어.
- 확인: `a|b*` = `{a, ε, b, bb, ...}`이라 `abbb`를 못 만든다. `(a|b)*`는 a, b로 만든 모든 문자열. 둘은 다른 언어.

**유한 상태 기계(FSM)**
- 상태들이 있고, 입력 문자를 하나 읽을 때마다 다른 상태로 옮겨간다(전이).
- 시작 상태는 하나, 수락 상태(accepting state)는 여러 개 가능.
- 입력을 다 읽었을 때 수락 상태에 있으면 accept, 아니면 reject. 중간에 수락 상태를 지나가는 건 상관없고 **마지막에 어디 있느냐**만 본다.

**집합 연산**
- 합집합 `S ∪ T`: 둘 중 어디든 속한 원소의 모음
- 곱집합 `S × T`: (s, t) 순서쌍의 모음
- 멱집합: S의 모든 부분집합을 원소로 갖는 집합. `S = {1,2}`이면 `{∅, {1}, {2}, {1,2}}`. 원소가 n개면 부분집합은 2^n개.
- Subset construction에서 "NFA 상태들의 집합 하나 = DFA 상태 하나"가 되는데 이때 멱집합 개념이 쓰인다.

**정규표현식 기본**: `a*`(0번 이상), `a+`(1번 이상), `[a-z]`(a~z 중 한 글자), `a|b`(a 또는 b)

## 1. Lexical Analysis 개요 *(슬라이드 p.2~6)*

### 컴파일러 안에서의 위치 *(p.2~3)*
Lexical Analysis는 **Scanner**라고도 부르고 Front end의 첫 단계. 소스코드를 처음 만나는 단계라 입력은 그냥 문자의 나열.

### 하는 일: 문자 나열을 단어(token)로 자르기 *(p.4)*
사람 언어에서 문장을 읽을 때 먼저 단어를 인식하는 것과 같다.
```
This is a sentence.
→ This(article) is(verb) a(article) sentence(noun) .(punctuation)
```
프로그램도 똑같다.
```
if (b == 0) a = b;
→ if(Keyword) ((Symbol) b(Identifier) ==(Symbol) 0(Constant) )(Symbol)
  a(Identifier) =(Symbol) b(Identifier) ;(Symbol)
```
- 이렇게 잘린 조각 하나하나가 **token**. token은 "종류(Keyword, Identifier, ...)"와 "실제 문자열"이 짝을 이룬 것.
- 이 단계는 문법이 맞는지는 신경 쓰지 않고 단어 단위로 자르고 분류만 한다.
- 위 예시의 token은 총 10개(괄호도 하나씩), Identifier는 3개(`b`, `a`, `b`).
- `x = 3 +;`처럼 문법이 틀린 문장도 각 조각은 멀쩡한 token이라 scanner는 통과시킨다. 문장 구조 오류는 다음 단계인 Syntax Analysis가 잡는다. Scanner가 잡는 건 `@`처럼 어떤 token 규칙에도 안 맞는 문자 정도.

### Token의 종류 *(p.6)*
| 종류 | 예시 |
|---|---|
| Identifiers | `x`, `y11`, `elsex` |
| Keywords | `if`, `else`, `while`, `for`, `break` |
| Integers | `2`, `1000`, `-20` |
| Floating-points | `2.0`, `-0.001`, `.02`, `1e5` |
| Symbols | `+`, `*`, `{`, `}`, `++`, `<<`, `<`, `<=` |
| Strings | `"x"`, `"TEST"`, `"Compiler"` |

- `elsex`는 `else` + `x`가 아니라 Identifier 하나. 키워드로 시작한다고 키워드가 되는 게 아님.
- `<`와 `<=`, `+`와 `++`처럼 앞부분이 같은 symbol이 있어서 "어디까지 읽고 자를까" 문제가 생긴다.
- 공백만으로 자르면 안 된다: 실제 언어는 공백이 필수가 아니라(`if(b==0)`) 공백 기준으로는 못 자른다. 대신 "가장 길게 맞는 규칙을 token으로 삼는다"(longest match)는 원칙을 쓴다.

### 생각보다 까다로운 이유: Fortran *(p.5)*
Fortran은 공백을 전부 무시하는 언어다.
```
do 5 I = 1.25
do 5 I = 1,25
```
- 첫 줄은 공백을 다 지우면 `do5I=1.25`. `do5I`가 통째로 하나의 Identifier이고, 실수 1.25를 대입하는 대입문.
- 둘째 줄은 `do`(Keyword), `5`(Label), `I`(Identifier)인 반복문. `1,25`는 반복 범위이고 `end do`까지 계속된다.
- 두 줄은 `.`과 `,` 한 글자만 다른데, 그 글자가 나오기 전까지는 앞의 `do`가 키워드인지 식별자의 일부인지 알 수 없다. 공백이 구분자 역할을 못 해서 뒤 문맥을 더 읽어봐야 하는 까다로운 경우.

## 2. 세 가지 하위 문제 *(p.7~8)*

Scanner를 만든다는 건 세 가지 질문에 답하는 것.

| 문제 | 질문 | 답(도구) |
|---|---|---|
| **Specification** | token의 모양을 어떻게 **적을** 것인가 | **Regular Expression (RE)** |
| **Recognition** | 적어둔 모양에 입력이 맞는지 어떻게 **판별**할 것인가 | **DFA** |
| **Automation** | RE에서 DFA를 어떻게 **자동으로** 만들 것인가 | Lex 같은 도구, Thompson's construction(RE→NFA), Subset construction(NFA→DFA) |

```
RE (사람이 씀) → NFA → DFA → 코드/테이블 (기계가 씀)
```
- RE는 사람이 쓰기 편하고, DFA는 컴퓨터가 돌리기 편하다. 둘 사이를 자동으로 잇는 게 Automation.
- 손으로 DFA를 만들면 오래 걸린다. 게다가 token 규칙이 바뀌면 RE 한 줄만 고치고 DFA는 기계가 다시 뽑으면 된다. DFA는 상태가 수십~수백 개가 되기도 해서 사람이 유지보수하기 어렵다.

## 3. Specification: Regular Expression *(p.9~14)*

### RE의 귀납적 정의 *(p.9)*
| 표기 | 의미 |
|---|---|
| `a` | 일반 문자 하나는 자기 자신 |
| `ε` | 빈 문자열 |
| `R\|S` | R **또는** S (alternation) |
| `RS` | R **다음에** S (concatenation) |
| `R*` | R을 **0번 이상** 반복 (closure, Kleene star) |

R, S는 이미 만들어진 RE. 이 규칙만으로 어떤 RE든 조합해서 만들 수 있다.

### RE가 나타내는 언어 `L(R)` *(p.10)*
RE `R`이 나타내는 문자열 집합을 `L(R)`이라 쓴다.
```
L(abc)            = {abc}
L(hello|goodbye)  = {hello, goodbye}
L(1(0|1)*)        = 1로 시작하는 모든 이진수 {1, 10, 11, 100, ...}
```
token 종류마다 RE가 하나씩 있다.
```
Keyword = L(if | else | while | break ...)
Integer = L( (-|+|ε) (1|2|...|9) (0|1|2|...|9)* )
```
Integer 정의: 부호는 `-`나 `+`나 없음 중 하나, 그 다음에 0이 아닌 숫자 하나, 그 뒤에 숫자가 0개 이상.

### 축약 표기(shorthand) *(p.11)*
| 표기 | 의미 | 풀어쓰면 |
|---|---|---|
| `R+` | 1번 이상 반복 | `R(R*)` |
| `R?` | 있어도 되고 없어도 됨 | `(R\|ε)` |
| `[abcd]` | 나열된 글자 중 **하나** | `(a\|b\|c\|d)` |
| `[a-z]` | 범위 안의 글자 하나 | `(a\|b\|...\|z)` |
| `[^ab]` | 나열된 글자를 **제외한** 아무 글자 | |
| `[^a-z]` | 범위에 **속하지 않는** 아무 글자 | |

새로운 표현력이 아니라 전부 기본 규칙으로 풀어쓸 수 있는 줄임말. 그래서 Thompson's construction에서는 기본 5개 규칙만 다루면 된다.

### 예시: 정수와 실수 *(p.12)*
```
digit    [0-9]              (또는 \d)
digits   digit+
pos_int  [1-9]digit*
int      (-? pos_int) | 0
real     int (.(pos_int | 0))?
```
- `pos_int`는 첫 자리가 1~9라 `007` 같은 앞자리 0은 막힌다.
- `int`는 (부호 optional + 양의 정수) 또는 그냥 `0`. `-0`은 나오지 않는다.
- `real`은 int 뒤에 `.`과 소수부가 optional로 붙는다.

이 정의에 경계 입력을 대입하면:
| 입력 | 결과 | 이유 |
|---|---|---|
| `3.14` | 매치 | int=`3`, 소수부 `14`는 pos_int |
| `3.10` | 매치 | 소수부 `10`은 pos_int |
| `-0.5` | 불일치 | `-0`은 int가 아님 |
| `.5` | 불일치 | 정수부(int)가 필수 |
| `3.001` | 불일치 | 소수부 `001`은 pos_int도 `0`도 아님 |

슬라이드의 예시도 완벽한 정의는 아니므로 RE는 경계를 직접 대입해서 확인해야 한다.

### Class Exercise *(p.13)*
- `[abc]` vs `abc`: `L([abc]) = {a,b,c}`(한 글자 중 하나) vs `L(abc) = {abc}`(3글자 연속). 완전히 다르다.
- 과학적 표기법(`-1.4E+17`, `-2.3E1`, `8.3E-2`):
  ```
  int          (-? pos_int) | 0
  opt_frac     (.digits)
  opt_exponent (E(+|-)?digits)
  sci_note     int opt_frac? opt_exponent?
  ```
  `opt_`는 optional이라는 뜻이라 실제로는 뒤에 `?`를 붙여 읽는다. frac에 `pos_int` 대신 `digits`를 쓰면 `3.001` 문제를 피할 수 있다.

### Multiple Matches: 여러 token이 매치될 때 *(p.14)*
`elsex = 0;`을 이렇게 자를 수도 있다.
```
(A)  else / x / = / 0 / ;
(B)  elsex / = / 0 / ;
```
Keyword RE(`else`)도, Identifier RE(`[a-zA-Z]+`)도 맞는다. 규칙:
1. **Longest match**: 매치되는 것 중 **가장 긴** 것. `else`(4) < `elsex`(5)라서 (B).
2. **Specification order**: 길이가 같으면 RE 목록에서 **먼저 적힌 규칙**이 이긴다.

확인:
- `ifx` → Identifier (longest match), `if` → Keyword (같은 길이, Keyword를 먼저 적었으므로 specification order), `iffy` → Identifier (longest match)
- Identifier를 Keyword보다 먼저 적으면 `if`, `else`가 전부 Identifier로 분류돼 키워드가 죽는다.
- `<=`를 읽을 때는 `<`와 `<=` 둘 다 매치되지만 longest match로 `<=`가 선택된다.

## 4. Recognition: Finite State Automata *(p.15~22)*

### FSA의 구성요소 *(p.16)*
- 입력(input) 문자열
- 유한한 개수의 상태(state)
- 시작 상태(start state) 하나
- 수락 상태(accepting state)들의 집합
- 상태에서 상태로 가는 전이(transition). "어떤 문자를 읽으면"이라는 조건이 붙는다.

예시로 `ab+`를 인식하는 기계:
```
 → (0) --a--> (1) --b--> ((2)) <--b-- (자기 자신으로)
```
0이 시작 상태, 2가 수락 상태(이중 원). 상태 2에서 `b`를 또 읽으면 2에 머문다.

### 동작 결과 3가지 케이스 *(p.17)*
| 케이스 | 상황 | 결과 |
|---|---|---|
| Case 1 | 입력을 다 읽었는데 **수락 아닌 상태**에 있음 | reject |
| Case 2 | 읽는 도중 그 문자에 대한 **전이가 없음** | reject |
| Case 3 | 입력을 다 읽었는데 **수락 상태**에 있음 | accept |

위 기계로:
- `abbb`: 0→1→2→2→2, 수락 상태 → Case 3, accept
- `a`: 1에서 끝남 → Case 1, reject
- `ba`, `b`: 시작 상태에서 `b` 전이가 없음 → Case 2, reject
- `abab`: 0→1→2까지 가고 2에서 `a` 전이가 없음 → Case 2, reject

### DFA vs NFA *(p.18)*
**DFA (Deterministic)**
- (상태, 입력) 쌍마다 전이가 **최대 하나**. (전이가 아예 없는 것도 허용되고 그게 Case 2. 엄밀히는 없는 전이를 "죽은 상태(dead state)"로 가는 걸로 보면 정확히 하나.)
- ε-move가 없다. 경로가 하나뿐.

**NFA (Non-deterministic)**
- 한 상태에서 한 입력에 대한 전이가 **여러 개**일 수 있다.
- **ε-move**(입력 문자를 소비하지 않고 상태를 옮기는 전이)가 가능.
- 가능한 경로가 여러 갈래라 그중 **하나라도** 수락 상태에 도달하면 accept.
- "동시에 여러 상태에 있다"거나 "정답 경로를 운 좋게 고른다"고 생각하면 편하다.

`ab|ac`의 NFA 예시:
```
(0) --a--> (1) --b--> ((3))
(0) --a--> (2) --c--> ((4))
```
상태 0에서 `a`를 읽으면 1과 2로 동시에 갈 수 있어 비결정적. `ab`가 들어오면 1을 거쳐 3에 도달하는 경로가 있으니 accept.

### DFA/NFA 예시 `AA*|B|AB` *(p.19~20)*
같은 RE를 DFA와 NFA로 그린 예시. DFA는 상태 0에서 입력마다 경로가 하나뿐이고, NFA는 ε-move 때문에 여러 상태(1,2,3 등)가 동시에 활성화됐다가 수락 상태로 모인다.

### 비교 *(p.21)*
| | DFA | NFA |
|---|---|---|
| state 수 | 일반적으로 더 많음 | 더 적음 |
| 구현 | 쉬움. 경로가 하나라 단순 순회 | 어려움. 여러 경로를 추적해야 함 |
| RE로부터 만들기 | (직접은 어려움) | **RE에서 쉽게 변환됨** |

- 전략: RE에서 만들기 쉬운 NFA를 먼저 만들고, 실행하기 쉬운 DFA로 바꾼다.
- 둘은 표현할 수 있는 언어가 같다. 표현력 차이는 없고 트레이드오프만 있다.
- NFA는 실행할 때 여러 경로를 동시에 추적해야 해서 느리다. DFA로 바꿔두면 문자당 O(1)에 끝난다.

### 전체 절차와 구현 *(p.22)*
```
RE → (Thompson's construction) → NFA → (Subset construction) → DFA → Table
```
DFA를 전이 표(transition table)로 만들면 구현이 단순한 루프가 된다.
```c
i = 0;
state = 0;
while (input[i]) {
    state = Table[state, input[i]];
    if (state == invalid) break;
    i++;
}
```
- `Table[state][문자]`가 다음 상태.
- invalid(전이 없음)가 나오면 바로 멈춘다(Case 2).
- 루프가 끝난 뒤 state가 수락 상태인지 검사해야 accept 여부가 정해진다(Case 1, 3). 슬라이드 코드엔 이 검사가 빠져 있다.

## 5. Automation ①: Lex/Flex *(p.24~32)*

### 왜 필요한가 *(p.24~25)*
RE → NFA → DFA → Table 변환을 직접 코딩하지 않고 **대신 해주는 프로그램**이 Lex. 프로그램을 만드는 프로그램.
- **Lex**: Bell Labs에서 만든 lexer 생성기. **Flex**는 그 빠른 구현체(지금은 보통 flex).
- **Yacc/Bison**: 짝이 되는 parser 생성기. Yacc는 "Yet Another Compiler-Compiler". Lex가 만든 token 스트림을 Yacc가 문법으로 해석한다.
- **입력**: 우선순위 순서의 RE 목록 + 각 RE에 연관된 action(C 코드)
- **출력**: 입력을 읽어 RE대로 token을 자르고 action을 실행하는 C 프로그램

사용 방법은 3단계:
```
1. 규칙 파일(foo.l)을 쓴다
2. flex foo.l     → lex.yy.c (lexer C 소스)가 만들어진다
3. gcc lex.yy.c   → 실행 파일
```
2번에서 Flex가 RE → NFA → DFA → 표 변환을 전부 해서 C 코드로 만들어준다.

### 명세의 3개 섹션 *(p.26)*
```
Definition section
%%
Rules section
%%
User function section
```
- **Definition section**: `%{ ... %}` 사이에 C 코드(include, 변수 선언). 자주 쓰는 패턴에 이름도 붙인다(`digit [0-9]`).
- **Rules section**: `패턴  {action}` 형태. "입력에서 이 패턴이 나오면 이 코드를 실행해라"는 뜻.
- **User function section**: C 함수를 결과물에 그대로 복사. 보통 `main()`을 여기에 쓴다.
- 세부사항은 man page: `https://man.freebsd.org/cgi/man.cgi?query=lex&sektion=1`

### Partial Flex 예시 *(p.27)*
```
digit    [0-9]
letter   [a-zA-Z]
%%
if          {return "IF";}
{letter}+   {return "Identifier";}
{digit}+    {return "decimal";}
```
왼쪽이 Pattern, 오른쪽이 Action. (슬라이드는 개념을 보여주려고 문자열을 return하는 의사코드에 가깝다.)

### 예제 ① count.l *(p.28)*
```
%{
    #include <stdio.h>
    int num_lines = 0;
    int num_chars = 0;
%}
%%
\n    {++num_lines; ++num_chars;}
.     {++num_chars;}
%%
main()
{
    yylex();
    printf("%d, %d", num_chars, num_lines);
}
```
```
flex count.l
gcc lex.yy.c -lfl
./a.out < examples.txt
```
- 파일을 글자 하나씩 읽으면서: 줄바꿈(`\n`)이면 줄 수와 글자 수를 올리고, 그 외 아무 글자(`.`)면 글자 수만 올린다. 다 읽으면 출력.
- `main`이 부르는 `yylex()`가 "Flex가 만든 scanner를 지금 실행해라"는 함수. 이게 호출돼야 규칙들이 돈다.
- 슬라이드 실행 예시는 파일 이름을 인자로 주는 방식이지만, 기본 Flex lexer는 stdin에서 읽으므로 리다이렉션이 필요할 수 있다.

### Lex가 제공하는 것들 *(p.29)*
**`yylex()`**
- 원형: `int yylex(void)`
- 이름 뜻: `yy`는 Yacc에서 온 접두어, `lex`는 lexical
- 파라미터 없음. 입력은 stdin(또는 `yyin`)에서 읽는다.
- 반환값: action에서 `return 값;`을 하면 그 값을 돌려주고 멈춘다. 어떤 action도 return하지 않으면 입력 끝(EOF)까지 계속 읽다가 0을 돌려준다.

**`yytext`**
- 원형: `char *yytext` (매치된 token 문자열)
- 이름 뜻: yy + text, 방금 매치된 text. token의 첫 글자를 가리키는 포인터.
- 다음 매치 때 덮어써지니 나중에 쓰려면 복사해둬야 한다.

**`yyleng`**
- 원형: `int yyleng`
- 이름 뜻: yy + length, 매치된 token의 길이

### 예제 ② complex.l *(p.29)*
```
%{
    #include <stdio.h>
%}
%%
[ \t]     { /* skip whitespace */ }
a |
an |
the       { printf("%s: is an article\n", yytext); }
[a-z]+    { printf("%s: ???\n", yytext); }
%%
main() { yylex(); }
```
- `a |`, `an |`처럼 action을 비우고 `|`만 쓰면 "다음 규칙의 action과 같다"는 뜻. `a`, `an`, `the` 셋이 같은 action을 쓴다.
- 입력 `the`는 관사 규칙(3글자)과 `[a-z]+`(3글자)에 둘 다 매치되는데 길이가 같으므로 **먼저 적힌 규칙**이 이겨서 article.
- 입력 `then`은 관사 규칙에서는 `the`(3글자)까지, `[a-z]+`에서는 `then`(4글자)이 매치. **longest match**로 `[a-z]+`가 이겨서 `???`.
- Lex는 longest match → 동점이면 먼저 적힌 규칙이라는 앞서 배운 원칙을 그대로 구현한다.
- 확인: `if` 규칙과 `[a-z]+` 규칙이 있고 입력이 `if`일 때 `if`가 선택되게 하려면 `if` 규칙을 앞에 적어야 한다.

### Lex 정규표현식 메타문자 *(p.30)*
| 메타문자 | 의미 |
|---|---|
| `.` | 줄바꿈(`\n`) 제외 아무 문자 하나 |
| `*` | 0회 이상 (Kleene closure) |
| `+` | 1회 이상 (positive closure) |
| `?` | 0회 또는 1회 |
| `\|` | 또는 (alternation) |
| `()` | RE 그루핑 |
| `[]` | 안의 문자 중 하나. 맨 앞 `^`는 집합 반전, 첫 위치의 `-`는 그냥 문자 `-` |
| `^` | 줄의 시작에 매치 (`[]` 밖에서) |
| `$` | 줄의 끝에 매치 |
| `{a,b}` | 앞 패턴을 a~b회 반복 (b는 생략 가능) |
| `\` | 메타문자 이스케이프 (`\.`은 진짜 점) |
| `/` | lookahead |
| `<>` | 특정 상태(start condition)에서만 패턴이 유효하도록 제한 |

### 리눅스 명령어 속 정규표현식 *(p.31~32)*
- `grep -n '\(TEST\)\+' test.txt`: `(TEST)+`가 들어 있는 줄을 줄 번호와 함께 찾는다. (기본 정규식에서는 `\(`, `\)`, `\+`처럼 백슬래시를 붙여야 그룹과 `+`로 동작한다.)
- `find -name "test*"`: 이름이 `test`로 시작하는 파일 찾기
- `sed -i 's/\(TEST\)\+/BEST/' test.txt`: `(TEST)+`를 `BEST`로 치환
- `awk '$1 ~ /fail/ {print $2}' file.txt`: 첫 필드에 `fail`이 있는 줄의 두 번째 필드만 출력. awk는 lex처럼 "패턴 {action}" 구조.

## 6. Automation ②: Thompson's Construction (RE → NFA) *(p.33~41)*

### 아이디어 *(p.33~36)*
RE가 작은 조각(문자, `ε`, `|`, 이어쓰기, `*`)의 조합이듯 NFA도 **작은 NFA 조각을 조합**해서 만든다. 기본 규칙 5개만 정해두면 어떤 RE든 NFA가 된다. 모든 조각은 **시작 상태 S 하나와 종료 상태 F 하나**를 가져서 끼워 맞추기 쉽다.
```
E  =  (S) ~~~[ E 내부 ]~~~ (F)
```
진입구 하나, 출구 하나만 있으면 어디에 끼워도 안전하다. 시작 상태를 마구 합쳐버리면 특히 `*`의 되돌아가기 ε가 붙을 때 원래 없던 경로가 생겨 다른 언어를 인식할 수 있다.

### 규칙을 예제로 유도 *(p.38~39)*
**① 문자 `x`**
```
(S) --x--> (F)
```
`ε`도 같은 모양이고 전이 라벨만 `ε`.

**② 이어쓰기 `E1 E2`** (예: `ab`): `a` 조각의 끝에서 `b` 조각의 시작으로 **ε 전이**를 놓는다.
```
(S1) --a--> (F1) --ε--> (S2) --b--> (F2)
```
전체 시작은 S1, 전체 종료는 F2.

**③ 또는 `E1 | E2`** (예: `a|b`): 새 시작에서 두 조각으로 갈라지고 끝에서 새 종료로 합쳐진다.
```
        ε        a        ε
   ┌──────> (S1) ──> (F1) ──────┐
(S)                               (F)
   └──────> (S2) ──> (F2) ──────┘
        ε        b        ε
```
갈라지는 지점에서 두 경로가 동시에 열리므로 NFA가 된다.

**④ 반복 `E*`**: 0번 이상 돌 수 있어야 하므로 두 가지 길이 필요하다.
- 건너뛰기(0번): 시작에서 종료로 바로 ε
- 되돌아가기(여러 번): E의 끝에서 E의 시작으로 ε
```
                 ┌────────── ε (되돌아가기) ──────────┐
                 v                                     │
(S) --ε--> (S_E) ~~~[ E ]~~~ (F_E) --ε--> (F)
 └──────────────────── ε (0번, 건너뛰기) ────────────┘
```
슬라이드 그림은 상태 이름과 배치가 조금 다를 수 있지만 "0번 건너뛰기 + 되돌아가기" 원리는 같다.

### 5개 규칙 요약 *(p.38~39)*
| RE | NFA 만드는 법 |
|---|---|
| `ε` | S --ε--> F |
| `x` | S --x--> F |
| `E1 E2` | F1 --ε--> S2로 연결 |
| `E1 \| E2` | 새 S에서 두 조각으로 ε 분기, 두 조각 끝에서 새 F로 ε 합류 |
| `E*` | 건너뛰기 ε + 되돌아가기 ε |

`R+`, `R?` 같은 축약 표기는 따로 규칙이 필요 없다. `R+ = R R*`, `R? = (R|ε)`로 풀어서 5개 규칙으로 만든다.

### 조합 예시: `(x|y)*` *(p.40)*
안쪽부터 바깥으로 조립한다.
- **Step 1**: 가장 작은 조각. `x: (0) --x--> (1)`, `y: (2) --y--> (3)`
- **Step 2**: `x|y`를 규칙 ③으로. 새 시작/종료를 놓고 ε로 연결.
  ```
     ε        x        ε
  ┌────> (0) ──> (1) ────┐
  (S)                     (F)
  └────> (2) ──> (3) ────┘
     ε        y        ε
  ```
- **Step 3**: 이 덩어리 전체를 `E`로 보고 규칙 ④로 `*`를 씌운다. 다시 새 시작/종료를 만들고 "0번 건너뛰기 ε"와 "되돌아가기 ε"를 놓는다.

조각을 붙이는 방식이 항상 같아서 프로그램이 기계적으로 할 수 있다.

### Exercise: `(+|-)?d+` *(p.41)*
조립 순서: `(+|-)?`는 `(+|-|ε)`로 풀고, `d+`는 `d d*`로 풀어서 각각 만든 뒤 concat으로 합친다.
```
(+|-)?  : 0에서 ε로 갈라져 +(1→2) 또는 -(3→4)를 거쳐 5로 합류, 또는 곧바로 5로 가는 ε(옵셔널)
d       : 5 --ε--> 6 --d--> 7
d*      : 7 --ε--> 8, 8↔9,10 loop(d), 8 --ε--> 11(최종)
```
`ab*`도 같은 방식: `a` 조각 + `b*` 조각(건너뛰기 ε와 되돌아가기 ε 둘 다)을 F_a --ε--> `b*`의 시작으로 이어 붙인다.

## 7. Automation ③: Subset Construction (NFA → DFA) *(p.42~51)*

### 해결해야 할 문제 *(p.42~43)*
Thompson으로 만든 NFA에는 두 종류의 비결정성이 있다.
- **ε 전이**: 문자를 안 읽고도 움직여서 지금 어느 상태에 있는지 애매해진다.
- **같은 입력에 갈 곳이 여럿**: 예를 들어 `a`를 읽으면 상태 1과 2로 동시에 갈 수 있다.

목표는 (상태, 입력) 쌍마다 갈 곳이 딱 하나인 DFA를 만드는 것. (예: `(a*|b*)c*`의 NFA는 ε로 두 경로(a-loop, b-loop)가 갈라졌다가 합류하는 구조.)

### 핵심 아이디어 *(p.44)*
**"지금 있을 수 있는 NFA 상태들의 집합"을 통째로 하나의 DFA 상태로 삼는다.** 그러면 DFA는 항상 딱 하나의 집합에만 있으니 결정적이다. 이를 위해 ε를 처리해야 한다.

**ε-closure(S)**: 상태 S에서 **ε 전이만 타고** 갈 수 있는 모든 상태의 집합(S 자신 포함).

슬라이드 예시 `a*b*`:
```
ε-closure(0) = {0,1,2},  ε-closure(1) = {1,2},  ε-closure(2) = {2}
Δ(ε-closure(0), a) → ε-closure(1)
Δ(ε-closure(0), b) → ε-closure(2)
Δ(ε-closure(1), a) → ε-closure(1)
Δ(ε-closure(1), b) → ε-closure(2)
Δ(ε-closure(2), b) → ε-closure(2)
```

### 예제 ①: ε 처리
```
(0) --a--> (0)        (a 루프)
(0) --ε--> (1)
(1) --b--> (1)        (b 루프)
수락 상태: 1
```
1. 시작: ε-closure(0) = {0,1} = **A**. 수락 상태 1을 포함하므로 A는 수락.
2. A에서 `a`: 0은 `a`로 0, 1은 `a` 전이 없음 → {0}, ε-closure = {0,1} = **A** (자기 자신).
3. A에서 `b`: 1이 `b`로 1 → {1}, ε-closure = {1} = **B** (수락).
4. B에서 `a`: 없음(dead). B에서 `b`: {1} = B.

결과: `A --a--> A`, `A --b--> B`, `B --b--> B`. 정확히 `a*b*`.

### 예제 ②: 같은 입력에 갈 곳이 여럿 (`ab|ac`)
```
(0) --a--> (1) --b--> ((3))
(0) --a--> (2) --c--> ((4))
```
- 시작 A = {0}
- A에서 `a`: {1,2} = **B**
- B에서 `b`: {3} = **C** (수락), B에서 `c`: {4} = **D** (수락)

"1과 2에 동시에 있다"가 DFA 상태 {1,2} 하나가 된다.

### 알고리즘
1. 시작 DFA 상태 = ε-closure(NFA 시작 상태)
2. 아직 처리 안 한 DFA 상태 T와 각 입력 문자 c에 대해
   - move(T, c) = T 안의 각 NFA 상태가 c로 갈 수 있는 상태들의 합집합
   - U = ε-closure(move(T, c)). 이게 T에서 c로 가는 DFA 상태.
   - U가 처음 보는 집합이면 새 DFA 상태로 추가
3. 새 상태가 더 안 나올 때까지 반복
4. 집합 안에 NFA 수락 상태가 하나라도 있으면 그 DFA 상태는 수락

- 4번의 이유: NFA의 accept 정의가 "여러 경로 중 하나라도 수락 상태에 도달하면 accept"이고, DFA 상태 집합은 "NFA가 있을 수 있는 모든 곳"이므로 그중 하나라도 수락이면 accept 가능.
- DFA 상태 수의 상한은 2^n(n은 NFA 상태 수, 부분집합의 개수). 실제로는 시작에서 도달 가능한 집합만 만들어서 보통 훨씬 적지만, 일부 RE는 정말 지수적으로 커진다. 그래서 "DFA는 일반적으로 상태가 더 많다".

### NFA to DFA 상세 예시와 Class Exercise *(p.45~46)*
p.45는 시작 상태의 ε-closure를 DFA 상태 A로 잡고, A에서 `a`, `b`로 갈 곳의 closure를 새 상태로 추가하는 걸 새 상태가 안 나올 때까지 반복해서 4개 상태짜리 DFA를 얻는 예시. p.46은 NFA를 `ε(0)`, `ε(3|8)`, `ε(5)`, `ε(5|9)` 네 개의 DFA 상태로 축약하는 연습. 알고리즘은 위와 동일.

확인 문제: 아래 NFA의 DFA.
```
(0) --a--> (0),  (0) --a--> (1),  (1) --b--> (2),  수락 상태: 2
```
```
A = {0}
A --a--> {0,1} = B
A --b--> 없음
B --a--> {0,1} = B
B --b--> {2} = C (수락)
```
`a+b`를 인식한다.

### DFA 최소화 *(p.47~49)*
subset construction으로 만든 DFA에는 **하는 일이 똑같은 중복 상태**가 있을 수 있다.

예제:
```
(0) --a--> (1) --c--> ((3))
(0) --b--> (2) --c--> ((3))
```
언어는 `(a|b)c`. 상태 1과 2는 둘 다 `c`를 읽으면 3으로 가고 다른 입력은 전이가 없어 어떤 입력에서도 똑같이 행동한다. 합치면:
```
(0) --a,b--> (12) --c--> ((3))
```

**구분 불가능(indistinguishable)**: 어떤 입력을 줘도 둘 다 accept이거나 둘 다 reject. 합칠 수 있다.
**구분 가능(distinguishable)**: 어떤 입력에서 결과가 갈린다.

슬라이드 예시:
```
Δ(2,a)=4 & Δ(2,b)=3,  Δ(3,a)=4 & Δ(3,b)=3  →  2와 3을 merge
Δ(0,a)=2 & Δ(0,b)=1,  Δ(1,a)=3(==2) & Δ(1,b)=1  →  0과 1을 merge
```

**반복 최소화 알고리즘**
1. 상태를 **수락 / 비수락** 두 집합으로 나눈다. (빈 문자열만으로도 결과가 갈리니 이미 구분 가능)
2. 각 집합 안의 상태 쌍 (i, j)에서, 어떤 입력 `a`에 대해 `Δ(i,a)`와 `Δ(j,a)`가 **서로 다른 집합**에 속하면 구분 가능이므로 다른 집합으로 쪼갠다.
3. 더 이상 쪼갤 게 없을 때까지 2를 반복. 남은 집합 하나가 최소 DFA의 상태 하나.

전이가 없는 경우는 "죽은 상태(dead)"로 가는 걸로 보고 그것도 하나의 집합으로 취급한다.

예제 적용:
```
시작:      {0,1,2}(비수락)   {3}(수락)
1회전:     0은 a로 {1,2}쪽으로 가는데, 1과 2는 a로 dead로 감 → 0을 분리
           {0}  {1,2}  {3}
2회전:     1과 2는 a→dead, b→dead, c→{3}으로 같음 → 변화 없음. 종료.
```
슬라이드 예시: `{0,3,5},{1,2,4}` → `{0,3},{5},{1,2,4}` → 변화 없음 → 최종 확정.

확인 문제 답:
```
0 --a,b--> 1 or 2,  1,2 --a,b--> 3,  3 --a,b--> 3,  수락: 3
시작:   {0,1,2}  {3}
1회전:  0은 a로 1(비수락 집합), 1은 a로 3(수락 집합) → 0과 1은 구분 가능.
        1과 2는 a→3, b→3 같음 → {0} {1,2} {3}
2회전:  변화 없음 → 종료. 1과 2가 합쳐짐 (4개 → 3개)
```

### 여러 RE를 동시에 처리하기 *(p.50)*
scanner는 token 종류가 여러 개라 RE도 여러 개. 하나의 DFA로 처리하려면:
1. 각 RE의 NFA를 만들고 **새 시작 상태에서 각 NFA로 ε 전이**를 놓아 **하나의 큰 NFA**로 합친다.
2. 이 NFA를 subset construction으로 DFA로 만든다.
3. DFA의 각 **수락 상태에 "어떤 token인가"를 붙여둔다**.

**Token Matching Rules**
1. 각 최종(accepting) state에 token을 연관시킨다.
2. 수락 상태를 만나도 **바로 멈추지 않고**, 더 진행 가능한 transition이 있으면 계속 읽는다(longest match). 더 갈 곳이 없으면 **마지막으로 지나친 수락 상태**의 token으로 결정.
3. 하나의 final state가 여러 token에 해당하면 **우선순위(priority, 명세 순서)**로 고른다.

`if` 규칙과 `[a-z]+` 규칙 예:
- 입력 `if`: `i`, `f`를 읽으면 DFA 상태에 IF의 수락 상태와 Identifier의 수락 상태가 둘 다 들어 있음 → priority로 Keyword.
- 입력 `ifx`: `f`까지는 같지만 더 읽을 수 있으니 계속 간다. `x`를 읽으면 Identifier쪽 수락 상태만 남으므로 Identifier.
- 수락 상태에서 바로 멈추면 `ifx`를 `if`(Keyword) + `x`(Identifier)로 잘못 자르게 된다.

### 전체 복습 *(p.51)*
```
RE들 → (Thompson) → NFA → (ε로 합치기) → (Subset construction) → DFA → (최소화) → Table
```
Table을 앞의 while 루프로 돌리면 scanner가 완성된다. Flex가 하는 일이 정확히 이 파이프라인.

## 강 전체 요약
- Scanner는 소스코드 문자열을 token(Keyword, Identifier, ...)으로 자르는 첫 단계.
- **RE**는 token 모양을 사람이 적는 도구, **NFA**는 RE에서 Thompson's construction으로 기계적으로 만들기 쉬운 중간 표현, **DFA**는 NFA에서 subset construction(ε-closure)으로 만들고 상태 최소화로 다듬은, 경로가 하나뿐이라 표와 while 루프로 빠르게 돌릴 수 있는 형태.
- 여러 token은 하나의 NFA/DFA로 합쳐 처리하고, longest match → priority 순으로 token을 정한다.
- Lex/Flex는 이 전체 과정을 자동화해 lexer(`lex.yy.c`)를 생성한다.

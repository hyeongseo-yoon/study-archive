# Chapter 17-3 수업노트: Amortized Analysis (Dynamic Table)

*정리 노트: `notes/기말고사/chapter-17-3.md` / 수업일: 2026-11-24*

## 0. 선수 개념 확인
- **Aggregate analysis**: n개 연산의 worst-case 총비용 T(n)을 구해 n으로 나눈 T(n)/n이 amortized cost. 연산마다 worst-case를 곱하는 것보다 tight하게 나온다.
- **Amortized analysis vs worst-case**: 연산 하나의 최악 비용이 아니라, 최악의 연산 sequence 전체의 연산당 평균 비용을 본다. 확률은 쓰지 않는다.
- **Accounting method의 credit**: 실제 비용보다 더 charge한 차액을 객체에 붙여 저장해 둔 것. 조건은 항상 `Σ ĉ_i ≥ Σ c_i`, 즉 credit이 0 이상.
- **Potential method 조건**: `Φ(D_i) ≥ Φ(D_0)`. 합이 telescoping돼서 `Σ ĉ_i = Σ c_i + Φ(D_n) − Φ(D_0)`가 되므로 이 조건이 있어야 `Σ ĉ_i ≥ Σ c_i`.
- 등비급수: `1 + 2 + 4 + ... + 2^j = 2^(j+1) − 1`.

## 1. Dynamic table *(p.59)*

**Dynamic table**: 저장할 객체 수를 미리 모를 때, 가득 차면 더 큰 table로 옮기고 너무 비면 더 작은 table로 옮기며 크기를 조절하는 배열.

- 가득 찬 크기 n table에 삽입하면 n개를 전부 복사해야 해서 삽입 한 번이 O(n). 그렇다고 n번 삽입이 O(n²)는 아니다(확장이 매번 일어나는 게 아니므로).
- 새 크기 정책에 따라 달라진다. expansion 한 번의 비용은 새 크기와 무관하게 **옮기는 항목 수**. 정책이 바꾸는 건 **확장이 얼마나 자주 일어나느냐**.
  - 슬롯을 1개씩만 늘리면 매번 확장해 총 O(n²).
  - n²처럼 크게 키우면 확장은 드물지만 공간 낭비가 심하다(load factor가 아주 낮음).
  - 2배는 확장이 드물고 낭비도 최대 절반이라 heuristic으로 쓴다 *(p.60)*.

## 2. TABLE-INSERT와 Aggregate analysis *(p.60~74)*
- 빈 table(size 0)에서 시작. 첫 삽입에서 1칸 할당, 이후 가득 차면 2배. 확장은 삽입 **직전**에 `T.num == T.size`일 때 일어난다.
- i번째 삽입 비용 `c_i`:
  - 자리가 있으면 1
  - 확장이 일어나면 i (새 항목 1 + 옮기기 i−1)
  - 즉 **i−1이 2의 거듭제곱일 때 `c_i = i`**, 아니면 1 (i가 아니라 i−1)
- n=8 예: `c_1..c_8 = 1, 2, 3, 1, 5, 1, 1, 1`, 합 15 (확장은 i=2, 3, 5. 8개를 옮기는 건 9번째 삽입이라 범위 밖).
- 총비용을 둘로 쪼갠다:
  - 새 항목을 넣는 비용: 모든 삽입에 1씩 → n
  - 옮기기 비용: 확장 시점에 table 안에 1, 2, 4, ..., 2^j개가 있고 `2^j ≤ n−1`. 합 `2^(j+1) − 1 < 2n`
  - n=8일 때 옮기기 비용 합은 1+2+4 = 7이다(한 번에 7개를 옮기는 게 아니라 8번 삽입 동안 옮긴 개수의 총합).
- 총비용 `< n + 2n = 3n` → amortized cost는 `3n/n = 3`, **O(1)**.
- 상한이 `n−1`이 아니라 `3n`인 이유: n=8에서 총비용 15는 3n=24 안에 들어가고 n−1=7은 넘는다. 옮기기 합이 n 미만이라고 한 건 틀린 판단(n=6이면 1+2+4=7 > 6). `2^j ≤ n−1`이면 `2^(j+1) ≤ 2(n−1)`이므로 합은 2n 미만.
- aggregate라는 이름의 이유: 연산별로 따로 값을 매기지 않고 n개 총비용을 한 덩어리로 구해 n으로 나눈다.

## 3. TABLE-INSERT와 Accounting method *(p.75~86)*
- 삽입 하나에 **3**을 charge. 크기 4 table이 가득 찬 상태에서 5번째 삽입 시 4개를 옮겨야 한다.
- 확장 직후 앞 절반(1~4)은 credit이 0이고, 새로 들어오는 5, 6, 7, 8은 각각 charge 3 중 1을 자기 삽입에 쓰고 **credit 2씩** 남긴다 → 합 8. 9번째 삽입의 확장에서 옮길 8개를 정확히 낸다.
- 항목 하나가 내는 3의 용도:
  1. 자기 자신을 table에 삽입
  2. 다음 확장 때 자기 자신을 옮기기
  3. 다음 확장 때 **이전 확장에서 이미 한 번 옮겨져 credit이 0인 오래된 항목**을 옮기기
- 조건 확인: 확장 직전 credit이 정확히 옮기는 개수만큼이고 쓰면 0. 음수가 되지 않으므로 `Σ ĉ_i ≥ Σ c_i`. amortized cost 3, aggregate 결과와 일치.
- **charge를 2로 하면?** 삽입당 credit이 1이라 새로 채워진 절반(5~8)이 쌓는 credit이 총 4인데 옮길 건 8개 → 필요한 것의 절반뿐이라 credit이 음수. 크기가 2배가 될 때마다 새로 채워지는 칸이 절반이라, 그 절반이 전체 옮기기를 책임지려면 항목당 2를 쌓아야 한다 → 3 = 1 + 2.

## 4. TABLE-INSERT와 Potential method *(p.87~94)*
- potential은 credit을 항목별로 나누지 않고 **상태 전체의 함수 하나**로 표현한다. 총량은 같다(크기 8 가득 찬 상태의 Φ = 8, accounting에서 5~8번째 credit 합도 8).
- 요구: 확장 직후 0, 가득 찰 때 table 크기(=항목 수).
- `Φ(T) = 2*T.num − T.size` *(p.89)*
  - (num 4, size 4): Φ = 4
  - 확장 직후 새 항목 삽입 전 (num 4, size 8): Φ = 0, 삽입 후 (num 5, size 8): Φ = 2
  - (num 8, size 8): Φ = 8
  - 확장 직전엔 `num = size`라서 `Φ = num`. 확장하면 size가 2배가 되며 Φ가 거의 0으로 떨어지고, 그 하락분이 옮기기 비용을 낸다.
- `ĉ_i = c_i + Φ_i − Φ_{i-1}`, `Φ_i`는 **i번째 연산이 완전히 끝난 뒤**(새 항목 삽입까지 끝난 뒤)의 값.
- 확장 없음 *(p.93)*: 삽입은 Φ를 +2 올린다. `ĉ_i = 1 + 2 = 3`. (예: num 5→6, size 8: Φ 2→4, `ĉ = 1 + 4 − 2 = 3`.)
- 확장 있음 *(p.94)*: `size_i = 2*size_{i-1}`, `size_{i-1} = num_{i-1} = num_i − 1`. `ĉ_i = num_i + 2 − (num_i − 1) = 3`. (예: 5번째 삽입, `c=5`, Φ 4→2, `ĉ = 5 + 2 − 4 = 3`.)
- **Φ ≥ 0 조건**: `2·num − size ≥ 0` ⟺ `num ≥ size/2`, table이 항상 최소 절반은 차 있어야 한다. 확장 직후 삽입까지 하면 `num = size_old + 1 > size_new/2`이고 이후 삽입만 하니 계속 성립. `Φ_0 = 0`이므로 `Φ_i ≥ Φ_0`.

## 5. TABLE-DELETE 단순 전략과 그 문제 *(p.95~108)*
- **Contraction**: 항목이 너무 적어지면 작은 새 table에 복사. **load factor** `α(T) = T.num / T.size`.
- 보존할 두 성질: ① α가 양의 상수로 아래에서 bounded, ② 연산의 amortized cost가 상수로 위에서 bounded.
- 단순 전략: 가득 차면 2배, 삭제 후 절반 미만이면 절반. load factor 1/2 이상은 보장되지만 문제가 있다.
- 반례 *(p.100)*: n(2의 거듭제곱)개 연산. 처음 n/2번은 insert(총 Θ(n)) → 크기 n/2에 항목 n/2개로 가득. 이후 **insert, delete, delete, insert, insert, delete, delete, ...**
  - 첫 insert에서 확장(n/2개 복사, 크기 n), delete·delete에서 축소(약 n/2개 복사, 크기 n/2), insert·insert에서 다시 확장...
  - 크기가 `n/2 ↔ n`을 왕복. **연산 2개마다 resize 한 번, 매번 약 n/2개 복사.**
  - 뒤쪽 n/2개 연산 동안 resize는 약 n/4번 → 총 `Θ(n²)`, amortized `Θ(n)`.
- **원인**: 축소 직후엔 새 table이 정확히 가득 차 있어 insert 하나로 확장되고, 확장 직후엔 약 절반만 차 있어 delete 몇 번이면 축소된다. 확장 임계점(가득 참)과 축소 임계점(절반)이 resize 직후 상태에서 너무 가까워, 다음 resize까지 남은 여유(slack)가 O(1)개뿐이라 Θ(n) 비용을 상쇄할 연산이 쌓일 틈이 없다.

## 6. 개선 전략과 potential function *(p.109~114)*
- 확장은 그대로(가득 차면 2배). 축소는 **α가 1/4 미만이 되면 크기를 절반**으로. load factor는 1/4 이상으로 bounded.
- 예: 크기 16, 항목 4개(α=1/4)에서 delete → 3개. 축소 후 크기 8, 항목 3개(α=3/8). 다음 resize까지: 확장은 5번의 insert, 축소는 delete 2번. 일반적으로 크기 S에서 resize 직후 α≈1/2이고 다음 resize까지 Θ(S)번의 연산이 필요 → resize 비용 Θ(S)를 그 사이 Θ(S)개 연산이 나눠 내 연산당 O(1). 확장·축소 임계점 사이에 α=1/2의 완충 구간(slack)이 생긴 것.
- 빈 table은 `num = size = 0`이고 `α = 1`로 둔다 *(p.110)*.
- potential function:
  - `Φ = 2·num − size` (α ≥ 1/2)
  - `Φ = size/2 − num` (α < 1/2)
- 크기 16에서: num 16 → Φ 16, num 8 → 0, num 4 → 4, num 6 → 2. **α=1/2에서 0이고 양쪽 임계점으로 갈수록 커지는 V자 모양**, 항상 0 이상.
- α=1: `Φ = num`, 확장 비용을 낼 수 있다 *(p.113)*. α=1/4: `size = 4·num`, `Φ = num`, 축소 비용을 낼 수 있다 *(p.114)*. α=1/2: Φ=0 (resize 직후와 같은 상태).
- 기호 *(p.115)*: `c_i, ĉ_i, num_i, size_i, α_i, Φ_i`는 i번째 연산 후 값, 초기 `num_0 = size_0 = 0, α_0 = 1, Φ_0 = 0`.

## 7. 개선 전략에서 TABLE-INSERT 분석 *(p.116~119)*
- `α_{i-1} ≥ 1/2`: 17.4.1 분석과 같다. 확장 여부와 상관없이 `ĉ_i ≤ 3`.
- `α_{i-1} < 1/2`이면 확장 불가(`size_i = size_{i-1}`, `num_{i-1} = num_i − 1`).
  - `α_i < 1/2`: `ĉ_i = 1 + (size/2 − num_i) − (size/2 − (num_i − 1)) = 0`. (예: 16에서 num 4→5, Φ 4→3, `ĉ = 1 + 3 − 4 = 0`.)
  - `α_i ≥ 1/2` (경계 통과): `ĉ_i = 1 + (2·(num_{i-1}+1) − size) − (size/2 − num_{i-1}) = 3·num_{i-1} − (3/2)·size + 3`. `α_{i-1} < 1/2`라 `num_{i-1} < size/2` → `ĉ_i < 3`. (예: 16에서 num 7→8, Φ 1→0, `ĉ = 1 + 0 − 1 = 0`.)
- TABLE-INSERT의 amortized cost는 항상 최대 3.

## 8. 개선 전략에서 TABLE-DELETE 분석 *(p.120~124)*
- `num_i = num_{i-1} − 1`.
- `α_{i-1} < 1/2`, 축소 없음 *(p.121)*: `ĉ_i = 1 + (size/2 − num_i) − (size/2 − (num_i + 1)) = 2`. (예: 16에서 num 6→5, Φ 2→3, `ĉ = 1 + 3 − 2 = 2`.)
- `α_{i-1} < 1/2`, 축소 발생 *(p.122)*: `c_i = num_i + 1`, `size_i/2 = size_{i-1}/4 = num_{i-1} = num_i + 1`. `ĉ_i = (num_i + 1) + (size_i/2 − num_i) − (size_{i-1}/2 − num_{i-1}) = 1`. (예: 16에서 num 4→3, 축소 후 크기 8, `c = 4`, Φ 4→1, `ĉ = 4 + 1 − 4 = 1`.)
- `α_{i-1} ≥ 1/2` *(p.123)*: amortized cost는 상수. `α_i < 1/2`가 돼도 축소는 일어나지 않는다(한 번의 delete로 α < 1/4까지 갈 수 없음). (예: num 12→11, Φ 8→6, `ĉ = 1 + 6 − 8 = −1`. 음수여도 상수 이하면 상관없다. num 8→7: Φ 0→1, `ĉ = 2`.)
- **결론** *(p.124)*: 각 연산의 amortized cost가 상수로 bounded → dynamic table에 대한 n개 연산 sequence의 실제 시간은 **O(n)**.

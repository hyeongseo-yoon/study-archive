**수업 목표**: 재귀 알고리즘의 running time을 recurrence로 세우고, substitution method와 recursion-tree method로 점근적 bound를 구할 수 있게 된다.

## 1. Recurrence 개념 *(p.3~4)*

**Recurrence(점화식)**: 어떤 함수를 더 작은 입력에서의 자기 자신의 값으로 정의하는 방정식 또는 부등식.

알고리즘이 자기 자신을 재귀 호출하면 running time T(n)도 "더 작은 입력의 T"로 표현된다. 예: merge sort

```
T(n) = Θ(1)            (n = 1)
T(n) = 2T(n/2) + Θ(n)  (n > 1)
```

- `2T(n/2)`: 크기 n/2짜리 부분문제 2개를 재귀로 푸는 비용 (divide 후 conquer)
- `Θ(n)`: 나누고 합치는 비용 (divide + combine)
- `Θ(1)`: n=1일 때 base case 비용

**Recurrence를 푼다는 것**: T(n)의 점근적 Θ 또는 O bound를 구하는 것. 위 식의 답은 Θ(n lg n).

**두 방법**
1. Substitution method: 답을 guess하고 귀납법으로 증명
2. Recursion-tree method: 재귀 호출을 트리로 펼쳐 비용을 합산. 좋은 guess를 만드는 데 사용

### 식 읽는 법: T(n) = a·T(n/b) + f(n)

T(n) = 3T(n/4) + n² 의 각 항:
- **3**: 재귀 호출 횟수 (부분문제 개수)
- **n/4**: 각 부분문제의 크기
- **n²**: 재귀 호출 말고 알고리즘 자체가 하는 일의 비용 (divide + combine)

일반형으로 a = 부분문제 개수, n/b = 부분문제 크기, f(n) = divide + combine 비용.

## 2. Substitution method *(p.5~12)*

**Substitution method**: 해의 형태를 먼저 guess하고, 수학적 귀납법으로 그 guess가 맞다는 것을 증명하는 방법.

1. 해를 **guess**한다.
2. **귀납법**으로 증명한다. basis(boundary condition)를 확인하고, inductive step에서 "더 작은 입력에서 성립하면 n에서도 성립"을 보인다.

### 예제: T(n) = 2T(⌊n/2⌋) + n *(p.6~11)*

Guess: T(n) = O(n lg n), 즉 적당한 c > 0에 대해 **T(n) ≤ cn lg n** 증명.

**Inductive step**: 귀납 가정은 "n보다 작은 모든 m에 대해 T(m) ≤ cm lg m". ⌊n/2⌋ < n이므로 T(⌊n/2⌋) ≤ c⌊n/2⌋ lg(⌊n/2⌋)을 쓸 수 있다.

```
T(n) = 2T(⌊n/2⌋) + n
     ≤ 2(c⌊n/2⌋ lg(⌊n/2⌋)) + n
     ≤ cn lg(n/2) + n
     = cn lg n - cn lg 2 + n
     = cn lg n - cn + n
     ≤ cn lg n        (c ≥ 1일 때)
```

- 둘째 → 셋째 줄: ⌊n/2⌋ ≤ n/2 이므로 2⌊n/2⌋ ≤ n, lg(⌊n/2⌋) ≤ lg(n/2). 부등호 방향 유지.
- lg(n/2) = lg n − 1
- −cn + n ≤ 0 이려면 c ≥ 1

### Boundary condition

n = 1에서 T(1) = 1 ≤ c·1·lg 1 = 0 은 **거짓**이라 깨진다. 하지만:

- T(1) = 1은 알고리즘의 실제 비용이므로 증명하려고 바꿀 수 없다. (정확한 값은 중요하지 않고 어떤 상수)
- O의 정의: "어떤 c와 n₀가 존재해서 **n ≥ n₀인 모든 n**에 대해 T(n) ≤ c·g(n)". 작은 n에서 깨져도 상관없다.
- 그래서 **n₀ = 2**로 잡아 n = 1을 증명 범위에서 뺀다.

basis를 n = 2, 3 두 개로 잡는 이유: inductive step에서 T(n)은 T(⌊n/2⌋)에 의존하는데 n ≥ 4이면 ⌊n/2⌋ ≥ 2. 그래서 n = 2, 3만 직접 확인하면 4 이상은 귀납으로 연결된다. n = 1에는 아무도 의존하지 않는다.

```
T(2) = 2T(1) + 2 = 4   ≤ c·2·lg 2 = 2c    → c ≥ 2면 만족
T(3) = 2T(1) + 3 = 5   ≤ c·3·lg 3 ≈ 4.75c → c ≥ 2면 만족
```

c ≥ 2로 잡으면 basis와 inductive step(c ≥ 1) 모두 만족. 결론: **n ≥ 2에서 T(n) ≤ 2n lg n → T(n) = O(n lg n)**.

만약 basis로 n = 2만 확인하고 3을 빼면, n = 3은 ⌊3/2⌋ = 1이라 귀납 가정으로 T(1) ≤ 0 (거짓)을 써야 해서 **n = 3에서 증명이 끊긴다**. n = 4, 5는 ⌊n/2⌋ = 2라 괜찮다.

**절차 정리**
1. guess를 세운다.
2. inductive step에서 필요한 c의 조건을 구한다.
3. basis가 깨지면 n₀를 키워서 피하고, basis에서 필요한 c의 조건과 합쳐서 c를 정한다.

### 흔한 실수 *(p.12)*

같은 recurrence에 T(n) = O(n)을 guess하고 T(n) ≤ cn을 증명하려는 경우:

```
T(n) ≤ 2(c⌊n/2⌋) + n
     ≤ cn + n
     = O(n)       ← 틀린 결론
```

- 증명하려던 문장은 **T(n) ≤ cn** (같은 c). 그런데 전개 결과는 **cn + n = (c+1)n**이라 같은 형태로 복원되지 않는다. cn + n ≤ cn은 거짓.
- 마지막에 "상수배니까 O(n)"으로 퉁치면 귀납 가정의 c가 매 단계 c+1, c+2, ...로 커지는 것을 무시한 것.
- 이 guess는 애초에 틀렸다. 진짜 답은 Θ(n lg n)이라 O(n)일 수 없다.

**규칙**: inductive step의 끝에서 **귀납 가정과 똑같은 형태(같은 c)** 가 나오는지 반드시 확인한다.

## 3. Recursion-tree method *(p.13~20, 22~25)*

**Recursion-tree method**: 재귀 호출을 트리로 펼쳐 각 노드에 그 호출이 "자기 몫으로" 쓰는 비용을 적고, 모든 노드의 비용을 합쳐 T(n)을 구하는 방법.

- substitution은 올바른 guess가 필요한데, recursion-tree는 **guess를 만드는 도구**.
- 절차: (1) 트리로 펼쳐 합산해서 guess를 만든다 (floor/ceiling 같은 디테일은 무시해도 됨) → (2) substitution으로 증명.

### 예제 1: T(n) = 3T(⌊n/4⌋) + Θ(n²) *(p.14~20)*

목표: T(n) = Θ(n²)
- **Ω(n²)**: 자명 (식에 이미 n² 항이 있음)
- **O(n²)**: recursion tree로 guess

n = 4ᵏ, T(n) = 3T(n/4) + cn²로 펼친다. depth i에서:
- 노드 개수: **3ⁱ** (그 층 하나만의 개수. 누적합이 아님)
- 부분문제 크기: **n/4ⁱ** (부모의 1/4씩)
- 노드당 비용: **c(n/4ⁱ)²**
- 층 총 비용: 3ⁱ · c(n/4ⁱ)² = **(3/16)ⁱ cn²**

트리의 끝: n/4ⁱ = 1 → **i = log₄n**. 레벨 수는 log₄n + 1.
마지막 층 노드 수: 3^(log₄n) = n^(log₄3) (항등식 a^(log_b c) = c^(log_b a)). 노드당 Θ(1)이므로 마지막 층 총 비용은 **Θ(n^(log₄3))**. (log₄3 ≈ 0.79)

```
T(n) = Σ(i=0 to log₄n-1) (3/16)ⁱ cn² + Θ(n^(log₄3))
     < Σ(i=0 to ∞) (3/16)ⁱ cn² + Θ(n^(log₄3))
     = 16/13 cn² + Θ(n^(log₄3))
     = O(n²)
```

마지막 줄은 n^(log₄3)가 n²보다 훨씬 작은 차수라 n² 항에 흡수되기 때문.

**지배적인 층은 루트**: 층별 비용이 cn², (3/16)cn², (3/16)²cn², ... 로 줄어서 첫 항이 가장 크고 나머지 전체 합도 cn²의 상수배(16/13)에 그친다.

**공비 3/16의 의미**: 한 층 내려가면 노드는 3배로 늘지만, 부분문제 크기가 1/4이 되고 비용이 크기의 제곱이라 노드당 비용은 1/16배. 층 총 비용은 3 × 1/16 = 3/16배씩 줄어든다. 공비가 1보다 작아 등비급수가 수렴하고, 무한합으로 바꿔도 상수배로 상한이 잡힌다.

**Substitution으로 증명** (T(n) ≤ dn² 가정):

```
T(n) = 3T(⌊n/4⌋) + cn²
     ≤ 3d⌊n/4⌋² + cn²
     ≤ 3d(n/4)² + cn²
     = 3/16 dn² + cn²
     ≤ dn²        (d ≥ (16/13)c 일 때)
```

3/16 dn² + cn² ≤ dn² → cn² ≤ (13/16)dn² → d ≥ (16/13)c. 끝 줄이 귀납 가정과 같은 형태(dn²)로 복원되므로 성립. Ω(n²)와 합쳐서 **T(n) = Θ(n²)**.

### 비교 예제: T(n) = 4T(n/4) + cn

depth i에서 노드 개수 4ⁱ, 노드당 비용 c·n/4ⁱ → 층 총 비용 4ⁱ · c(n/4ⁱ) = **cn**. 공비가 1 (노드 4배 × 비용 1/4배가 상쇄).

- f(n) = n²: 노드 3배 × 비용 1/16배 = 3/16 → 줄어듦 → 루트가 지배 → Θ(n²)
- f(n) = n: 노드 4배 × 비용 1/4배 = 1 → 층마다 같음 → **층 수가 곧 답**. 층 수 log₄n + 1 → Θ(n lg n)

### 예제 2: T(n) = T(n/3) + T(2n/3) + O(n) *(p.22~25)*

목표: T(n) = O(n lg n). 부분문제 크기가 n/3, 2n/3로 달라서 트리가 비대칭.

층별 비용:
- depth 0: cn
- depth 1: c(n/3) + c(2n/3) = cn
- depth 2: n/9, 2n/9, 2n/9, 4n/9 → c(1/9+2/9+2/9+4/9)n = cn

쪼갠 크기의 합이 부모와 같으므로, base case에 닿기 전 층의 비용은 항상 **cn**. 따라서 Total = (층당 cn) × (트리 높이).

**트리 높이**: 가장 깊은 경로는 크기가 천천히 줄어드는 **2n/3 쪽**. k번 내려가면 (2/3)ᵏn이므로

```
(2/3)ᵏ n = 1 → n = (3/2)ᵏ → k = log_(3/2) n
```

짧은 쪽(n/3)은 일찍 끝나므로 깊은 층에는 노드가 빠져 있고(완전 이진 트리가 아님) 그 층의 비용은 cn보다 작다. 하지만 상한(O)만 구하면 되므로 모든 층을 cn으로 쳐도 된다.

```
Total ≤ cn · log_(3/2) n = O(n lg n)
```

밑 변환으로 lg n의 상수배(1/lg(3/2))이므로 O(n lg n). → guess.

**Substitution으로 증명** (T(n) ≤ dn lg n 가정):

- lg(n/3) = lg n − lg 3
- lg(2n/3) = lg n − (lg 3 − 1)

```
T(n) ≤ T(n/3) + T(2n/3) + cn
     ≤ d(n/3)lg(n/3) + d(2n/3)lg(2n/3) + cn
     = dn lg n - d[(n/3)lg 3 + (2n/3)(lg 3 - 1)] + cn
     = dn lg n - d[n lg 3 - 2n/3] + cn
     = dn lg n - dn(lg 3 - 2/3) + cn
     ≤ dn lg n        (d ≥ c/(lg 3 - 2/3) 일 때)
```

lg 3 ≈ 1.585 → 분모 ≈ 0.918 > 0 이므로 d가 존재. 귀납 가정과 같은 형태로 복원되므로 성립 → **T(n) = O(n lg n)**.
